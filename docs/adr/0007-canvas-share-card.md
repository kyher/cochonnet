# Canvas-rendered Share Card doubles as the game-over screen

The end-of-session screen needed two things at once: a richer result recap (a per-end score breakdown, not just the total) and a way to produce a real shareable image, rather than just a screen a player could manually screenshot. Instead of adding a DOM-to-image library (e.g. html2canvas/html-to-image) to snapshot the existing CSS-styled screen, the game-over screen is now drawn directly onto a `<canvas>` — a new `render/shareCard.ts`, in the same spirit as the game board's own canvas drawing in `render/draw.ts`. That canvas *is* the visible screen the player sees, not a hidden second canvas kept in sync with a separate DOM display, so there's exactly one implementation of this screen's layout to maintain, and the exported PNG is guaranteed to match pixel-for-pixel what the player looked at.

This adds zero new runtime dependencies (the project has none beyond React today) and sidesteps the well-known flakiness of DOM-to-image libraries with gradients, custom fonts, and shadows. The trade-off: the card's layout is hand-coded in canvas draw calls rather than CSS, which costs more code for a comparably rich layout.

The card draws from the game canvas's existing fixed hex color palette (`render/draw.ts`) rather than the app's light/dark CSS theme variables — consistent with ADR-0005's precedent that the canvas and CSS color systems are intentionally kept separate. It doesn't reuse that palette literally, though: an early version put the card's content panel in the terrain's sandy tan, which read as a muddy, low-contrast combination for a card meant to pop when shared, and left the footer URL (drawn in the cream line-of-play color) nearly illegible against it. The panel is cream instead — the line-of-play color repurposed as a paper-like surface — with dark ink text throughout and the cochonnet red reserved as the one saturated accent, on the total score alone. The card is deliberately text-only (title, date, total score, per-end breakdown, site URL) rather than a rendering of the actual terrain/boule layout, since no per-boule position or zone data survives past the moment its floating feedback disappears (see ADR-0006).

The share action copies the rendered PNG directly to the clipboard (`navigator.clipboard.write` with a `ClipboardItem`) rather than triggering a file download or attempting `navigator.share` — a paste is one gesture away from Messages/Instagram/etc. on the platforms that support it, closer to how people actually share a screenshot than a downloaded file sitting in a Downloads folder. Where the Clipboard API's image support isn't available, the button just reports "Could not copy" with no download fallback — keeping the one code path simple, at the cost of no image path at all on unsupported browsers. That old text-share button (`navigator.share`/clipboard-copy of a text summary) is removed entirely; the screen now has exactly two actions: Copy image and Play again.

## Considered Options

- **Add a DOM-to-image library** (html2canvas/html-to-image) to snapshot the existing CSS screen — rejected: a new dependency, and these libraries are known to render gradients/custom fonts/shadows unreliably.
- **Keep the CSS-styled screen for display and render a second, hidden canvas purely for the export image** — rejected: two layouts to keep visually in sync is a maintenance burden the single-canvas approach avoids entirely.
- **Render a mini terrain/boule diagram on the card** showing where boules landed — rejected for this pass: no per-boule position/zone data survives past the current end today, and adding that persistence was out of scope.
- **Always trigger a file download** instead of copying to the clipboard — rejected: a copy-then-paste is a more direct route into a chat/social app than a file the player has to attach manually.
- **Fall back to downloading the file when clipboard image-write is unsupported** — rejected for this pass in favor of a plain error state, to keep the single clipboard code path simple; can be revisited if unsupported browsers turn out to matter in practice.
